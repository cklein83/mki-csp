Schritt 3

Bedarf in Slot-Grenzen umrechnen

Zelle 12
def demand_bounds(week_df, n_slots=N_SLOTS):
    groups = dict(zip(
        week_df["study_program"],
        week_df["course_groups"] * week_df["cohorts"]
    ))

    total_of_week = sum(groups.values()) # Gesamtbedarf dieser Woche

    # Rechnung für lo, hi
    # Anzahl Kursgruppen des Studiengangs (g) * Gesamt-Slots (n_slots) im Verhältnis zu Anzahl Kursgruppen der Woche (total_of_week)
    return {
        s: (
            math.floor((g * n_slots) / total_of_week), # lo
            math.ceil((g * n_slots) / total_of_week) # hi
        )
        for s, g in groups.items() # s = StudyProgram, g=Kursgruppen
    }
    # ergibt Return Wert mit Dict s: (lo, hi)

Für jeden Studiengang wird sein Anteil an allen Kursgruppen der Woche auf n_slots hochgerechnet und dann ab- und aufgerundet. Das Ergebnis ist ein Dict {studiengang: (lo, hi)}.

Dieselbe Funktion wird zweimal benutzt: mit dem Standardwert n_slots = 40 für die ganze Woche und mit n_slots = 8 für einen einzelnen Tag.

Woche 1, Σ g = 20
Schritt 4

Das Modell aufbauen

CP-SAT kennt keine Variablen mit Werten wie „MB“. Deshalb gibt es für jede Kombination aus Slot und Studiengang eine Boolesche Variable x[v, s]: 1 heißt „Slot v gehört Studiengang s“.

Zelle 15 · Teil 1
from ortools.sat.python import cp_model

def build_csp(week):
    week_df = exam_weeks[exam_weeks["exam_week"] == week]
    programs = week_df["study_program"].tolist()   # D: nur Studiengänge dieser Woche

    model = cp_model.CpModel()
    x = {(v, s): model.NewBoolVar(f"{v}_{s}") for v in variables for s in programs} # variables kommt von der Definition am Anfang des Dokuments
    # Beispiel: ('Mo_A_R1', 'ES'): Mo_A_R1_ES(0..1)

    # In einem Slot kann nur genau 1 Studiengang enthalten sein (umgekehrt bereits durch Modell abgesichert)
    for v in variables:
        model.AddExactlyOne(
            x[v, s] for s in programs
        )

programs enthält nur die Studiengänge dieser Woche. Damit ist die Domäne festgelegt.

AddExactlyOne verlangt, dass in jeder Zeile genau eine 1 steht. Ein Slot gehört also genau einem Studiengang.

Ausschnitt aus x (Woche 1, gelöst)

    # -> Bedarf pro Woche

    for day in weekdays:

        for s, (lo, hi) in demand_bounds(week_df, SLOTS_PER_DAY).items():
            model.AddLinearConstraint(
                sum(x[v, s] for v in day_vars),

                hi
            )

sum(x[v, s] for v in variables) rechnet hier noch nichts aus. Weil x Solver-Variablen enthält, entsteht ein linearer Ausdruck, den CP-SAT erst beim Lösen auswertet.

AddLinearConstraint(ausdruck, lo, hi) heißt: lo ≤ ausdruck ≤ hi. Das passiert einmal pro Studiengang für die Woche und einmal pro Studiengang und Tag für die 8 Slots dieses Tages.

Woche 1 erzeugt so 5 Wochen- und 25 Tagesbedingungen.

# Wochentage im Code ("Mo") -> Namen in preferences.json ("Montag")
day_names = {"Mo": "Montag", "Di": "Dienstag", "Mi": "Mittwoch", "Do": "Donnerstag", "Fr": "Freitag"}

# Popularität eines Slots berechnen - p(d, t)
def popularity(day, slot):
    weekday_pop = prefs["weekday_preferences"][day_names[day]]
    slot_pop = prefs["time_slot_preferences"][slot]["preference"]
    return weekday_pop + slot_pop

# Popularität für alle Slots berechnen
pop = {}

for v in variables:
    day, slot, _ = v.split("_")
    pop[v] = popularity(day, slot)

# Beispiel: {'Mo_A_R1': 9, 'Mo_A_R2': 9, 'Mo_B_R1': 10, ...}
#print(pop)

POP_TOL = 0.5   # erlaubte Abweichung der mittleren Popularität vom Wochenmittel

popTotal = sum(pop.values())
#print(f"pT: {popTotal}")

print("mittlere Popularität aller Slots:", popTotal / N_SLOTS)

popularity(day, slot) addiert Tages- und Slotwert. day_names übersetzt dafür die Kürzel im Code in die Schlüssel der JSON-Datei.

pop speichert den Wert für jede der 40 Variablen. Beide Räume eines Zeitpunkts haben denselben Wert. popTotal ist immer 266, der Mittelwert also 6,65.

Zelle 19
def add_popularity_constraints(model, x, programs):
    #popTotal = sum(pop.values())     # 266 = Summe der Popularität aller 40 Slots # schon oben definiert
    tol = round(POP_TOL * N_SLOTS)    # 0.5 * 40 = 20 (Toleranz, ebenfalls mit 40 multipliziert)

    for s in programs:
        n_s = sum(x[v, s] for v in variables)   # Anzahl Slots von s (lineare Summe, wie beim Bedarf)

        # Abweichung vom Mittel, mit 40 multipliziert, damit alles ganzzahlig bleibt:
        # (40 * p(v) - 266) ist > 0 für überdurchschnittliche und < 0 für unterdurchschnittliche Slots
        deviation = sum(
            (N_SLOTS * pop[v] - popTotal) * x[v, s] 
            for v in variables
        )

        model.Add(deviation <= tol * n_s)    # nicht zu viele attraktive Slots
        model.Add(deviation >= -tol * n_s)   # nicht zu viele unattraktive Slots

Jeder Slot bekommt den Faktor 40 · p − 266. Positiv heißt besser als der Durchschnitt, negativ heißt schlechter. Die Summe über die Slots eines Studiengangs muss zwischen −20 · n_s und +20 · n_s liegen.

Faktor 40 · p − 266 je Tag und Slot
Nachgerechnet: INF in Woche 1

PAR_SHARE = 0.5   # Mindestanteil der Slots in Parallelpaaren (für g >= 3)

def structure_rule(g):
    # passende Regel aus preferences.json zur Gruppenzahl g finden
    # condition ist ein String wie "course_groups >= 3" und wird mit eval ausgewertet
    for rule in prefs["appointment_structure_preferences"]:
        if eval(rule["condition"], {"course_groups": g}):
            return rule

for g in [1, 2, 3, 8]:
    r = structure_rule(g)
    print(f"{g} Gruppen -> parallel: {r['parallel']}  aufeinanderfolgend: {r['sequential']}")

structure_rule(g) sucht die passende Regel aus preferences.json. Die Bedingung steht dort als Text, z. B. "course_groups >= 3". eval wertet diesen Text aus, wobei course_groups auf g gesetzt wird.

PAR_SHARE = 0.5 legt fest, welcher Anteil der Slots großer Studiengänge mindestens in Parallelpaaren liegen muss.

Zelle 22 · Teil 1: Hilfsvariablen
def add_structure_constraints(model, x, week_df, programs):
    groups = dict(zip(week_df["study_program"], week_df["course_groups"] * week_df["cohorts"]))
    bounds_week = demand_bounds(week_df)

    for s in programs:
        rule = structure_rule(groups[s])
        parallel, sequential = [], []   # Hilfsvariablen sammeln, um sie später zu zählen

        for day in weekdays:
            used = {}
            for t in slots:
                r1, r2 = x[f"{day}_{t}_R1", s], x[f"{day}_{t}_R2", s]

                par = model.NewBoolVar(f"par_{day}_{t}_{s}")
                model.AddMinEquality(par, [r1, r2])          # 1, wenn s beide Räume hat
                parallel.append(par)

                used[t] = model.NewBoolVar(f"used_{day}_{t}_{s}")
                model.AddMaxEquality(used[t], [r1, r2])      # 1, wenn s mind. einen Raum hat

            for t1, t2 in zip(slots, slots[1:]):             # (A,B), (B,C), (C,D)
                seq = model.NewBoolVar(f"seq_{day}_{t1}{t2}_{s}")
                model.AddMinEquality(seq, [used[t1], used[t2]])   # 1, wenn s beide Zeitslots hat
                sequential.append(seq)

Pro Tag, Slot und Studiengang entstehen drei Hilfsvariablen:

  • par = min(R1, R2): 1 nur, wenn beide Räume diesem Studiengang gehören.
  • used = max(R1, R2): 1, wenn mindestens ein Raum ihm gehört.
  • seq = min(used[t1], used[t2]): 1, wenn er zwei benachbarte Zeitslots hat.
Beispiel: MB am Montag, Woche 1

        # g = 1: allowed = false -> verboten
        if not rule["parallel"]["allowed"]:

Bei allowed: false (INF mit 1 Kursgruppe) muss die Summe aller par bzw. seq 0 sein.

Ist parallel stärker bevorzugt (6 > 3), gelten zwei Bedingungen: (a) mindestens so viele Parallelpaare wie aufeinanderfolgende Paare und (b) eine Mindestzahl an Parallelpaaren, z. B. MB in Woche 1: floor(16 · 0.5 / 2) = 4.

ET mit 2 Kursgruppen hat Präferenz 0 / 0 und erlaubt beides. Für ET greift keine der beiden if-Bedingungen.

Schritt 7

Lösen

Zelle 15 · solve
def solve(model, x):
    solver = cp_model.CpSolver()
    status = solver.Solve(model)
    if status not in (cp_model.OPTIMAL, cp_model.FEASIBLE):
        return None
    return {v: s for (v, s), var in x.items() if solver.Value(var)}

CpSolver().Solve(model) sucht eine Belegung aller Booleschen Variablen, die jede Bedingung erfüllt. Da das Modell keine Zielfunktion hat, bedeutet OPTIMAL hier nur „zulässige Lösung gefunden“.

Am Ende wird x wieder in die fachliche Form übersetzt: Für jeden Slot wird der Studiengang mit Wert 1 übernommen. Ergebnis: {'Mo_A_R1': 'MT', 'Mo_A_R2': 'MT', …}.

Achtung: Ist ein Modell unlösbar, gibt solve None zurück. Die Schleife in Schritt 9 ruft dann show_plan(None) auf und bricht mit AttributeError ab.

def show_plan(solution):
    rows = [
        {
            "Tag": v.split("_")[0], 
            "Slot": v.split("_")[1], 
            "Raum": v.split("_")[2], 
            "SG": s # study_program
        }
        for v, s in solution.items()
    ]
    
    #plan = pd.DataFrame(rows)
    #print (plan)
    #     Tag   Slot Raum  SG
    # 0   Mo    A    R1    INF
    # 1   Mo    A    R2    DS

    plan = pd.DataFrame(rows).pivot(
        index=["Slot", "Raum"], 
        columns="Tag", 
        values="SG"
    )
    return plan[weekdays]

def slots_per_day(solution):
    rows = [
        {
            "Tag": v.split("_")[0], 
            "SG": s # study_program
        } 
        for v, s in solution.items()
    ]

    df = pd.DataFrame(rows)
    return pd.crosstab(
        df["SG"], 
        df["Tag"]
    )[weekdays]

show_plan zerlegt jeden Variablennamen in Tag, Slot und Raum und baut daraus mit pivot eine Tabelle: Zeilen = Slot und Raum, Spalten = Tage.

slots_per_day zählt mit crosstab, wie viele Slots jeder Studiengang an jedem Tag hat. Damit lässt sich die Tagesgrenze aus Schritt 4 direkt prüfen.

Zelle 23 · pop_and_struc() anzeigen 
def pop_and_struc(solution):
    rows = []

    # Jeden Studiengang einzeln betrachten
    for s in sorted(set(solution.values())):

        # Alle Slots dieses Studiengangs sammeln
        own = []
        for v, sg in solution.items():
            if sg == s:
                own.append(v)

        # Die belegten Tage und Zeitslots speichern
        times = set()
        for v in own:
            teile = v.split("_")
            tag = teile[0]
            slot = teile[1]
            times.add((tag, slot))

        # Gleichzeitige Prüfungen in beiden Räumen zählen
        parallel = 0
        for d in weekdays:
            for t in slots:
                if (solution[f"{d}_{t}_R1"] == s and
                    solution[f"{d}_{t}_R2"] == s):
                    parallel += 1

        # Direkt aufeinanderfolgende Prüfungen zählen
        sequential = 0
        for d in weekdays:
            for i in range(len(slots) - 1):
                t1 = slots[i]
                t2 = slots[i + 1]

                if (d, t1) in times and (d, t2) in times:
                    sequential += 1

        # Durchschnittliche Popularität berechnen
        durchschnitt = sum(pop[v] for v in own) / len(own)

        # Ergebnisse speichern
        rows.append({
            "SG": s,
            "Slots": len(own),
            "mittl. Popularität": round(durchschnitt, 2),
            "parallel": parallel,
            "aufeinanderfolgend": sequential
        })

    # Ergebnisse als Tabelle zurückgeben
    return pd.DataFrame(rows).set_index("SG")

pop_and_struc zählt am fertigen Plan nach, was der Solver einhalten sollte: Slots, mittlere Popularität, Parallelpaare und aufeinanderfolgende Paare. Die Funktion rechnet unabhängig vom Modell und eignet sich deshalb als Grundlage für die Validierung aus 4.6.
